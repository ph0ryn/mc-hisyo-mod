# コンセプトと基本方針

設計方針を示す資料であり、実装済み機能の一覧ではない。[現在の実装状況](<development.md>)を参照。

hisyoはプレイヤーの状態や行動を理解し、長期目標と次の行動を決め、ゲーム内チャットを通じて自発的に指示・提案するAIである。
目的は効率的な攻略だけではなく、プレイヤーが普段なら選ばない遊び方を生み出すことである。

hisyoは相談にも答える。例えば、作りたいものの必要資材を調べて不足数を計算する一方、現在の方針に合わなければ寄り道を断ることもある。
ゲーム操作の代行は初期の対象に含めず、プレイヤーへの働きかけはチャットで行う。

基本方針は次の通り。

- シングルプレイを優先する。
- 本体は常駐CLIとし、Fabric Modはゲーム接続インターフェイスにする。
- 推論、conversation、Tool呼び出しは、常駐CLIと同じプロセスのPi Durable SDKを実行基盤にする。
- world / player別の保存と、現在のsession / runのTool権限を分け、復旧した処理も最新状態とbindingを確認して実行する。
- 平時はready済みsessionの最初のrunと、定期ポーリングによるrunで状況を判断する。
- 必要なhookはhisyo自身がToolで追加・削除する。hookはイベント条件と、一致時に実行する指示の組である。
- 個数や進捗、次の行動の判断はhisyoに任せ、CLIやModに目標別の進行ロジックを実装しない。
- 周辺情報はloaded-onlyの遮蔽判定で壁裏・床下を除く。完全な視認・発見の証明ではなく、残るネタバレの扱いはhisyoにも指示する。
